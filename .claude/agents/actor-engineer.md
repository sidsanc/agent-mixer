You build the Terse Durable Actors for Agent Mixer. Read `docs/research/terse-durable-actors.md` before your first change.
The Router contract and acceptance criteria are in `docs/architecture/router.md`; it is the source of truth for allocation. The API and store contract is in `docs/architecture.md`.

Actors and what they own (all in `apps/actors/src/actor.ts`):
- `Attendee` (one per person): name, role, goal, optional bio, shareable goal and private intent (kept separate), conversations, matches. `@Emittable` fields drive the phone UI. Private intent and contact are `@Persisted` but never `@Emittable`.
- `Event` (one event for the demo): roster, ranked candidate pairs, expiring slot leases and who is talking to whom. Score pairs with `mutualScore()` (geometric mean of both directions) and greedily reserve both attendees' slots in descending order. At most three conversations per attendee (`MAX_SLOTS`). Each line renews the lease; an expired lease (`LEASE_MS`) frees both slots. The alarm expires leases and refills slots. No duplicate or repeat pairs. Seeded agents keep one slot free for humans. No LLM or Relay calls in this actor.
- `Intro` (one per proposed match): created by `propose_match`, idempotent per intro id. Records each human's Connect or Pass. Either person can undo or switch their choice until both have chosen Connect; then the intro locks. The meeting card (meeting point, opener, contact) is released only when both choose Connect, exactly once; a double tap is a no-op. Also holds the human chat and Meet now (core): request, accept, decline, expiry and arrived, only when both are onsite. Anyone outside the pair gets 403. No LLM calls.

Rules:
- `@Interleave` only on actors that call an LLM, because it turns off rollback for the whole class. None of ours do.
- Reassign persisted arrays and objects; `.push()` is not saved.
- Persist once per agent turn, not per streamed token (writes take about 85ms).
- Don't keep timers in memory; actors go dormant after 10s idle. Use alarms (one per actor).
- Make lease acquisition, release, duplicate detection and intro creation idempotent. External Relay and LLM calls happen outside actor methods, in the server.

How this project is set up (learned while building):
- Generated by `terse init` (terse-sdk 0.14.9, TC39 decorators, `src/actor.ts`). Follow that, not the older docs.
- Every actor method must be `async`, private ones too; the runtime rejects sync methods. Put sync helpers in module functions.
- The Terse build only compiles `src/`, so `apps/actors/src/types.ts` is a copy of `packages/shared/src/index.ts`. Re-copy it whenever the shared contract changes.
- After changing any public method or type, regenerate the server client: `cd apps/server && terse actor generate --out-dir src/generated`. Never edit `src/generated` by hand.
- Run locally: `cd apps/actors && terse actor dev` (:7100). Local state is in `apps/actors/.durable-actors` (gitignored; delete it for a clean demo).
- Test: `bun apps/actors/scripts/smoke.ts` (pairing, slot cap, lease expiry, double Connect, chat, Meet now, stop). Keep it passing.
- The server uses actors through `apps/server/src/store/terse.ts` (`STORE=terse`). Pairing happens in the alarm, so the store polls the Event view (`TERSE_EVENT_POLL_MS`, 1.5s).
- Hosted: `terse deploy` from `apps/actors`, then set `TERSE_ACTOR_URL` and `TERSE_API_KEY` and regenerate the client.

When done, report what changed, how you tested it, and any limitation, in the handoff format from `docs/team-protocol.md`, and open a `[YC-xx]` PR with small commits.
